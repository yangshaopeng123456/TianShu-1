# 天枢一号使用说明

## 首次运行

先按[根目录说明](../README.md)安装 Windows x64/Python 3.13 依赖、Node 依赖和 OpenDSS COM。本轮使用 Node.js 24.19.0，Electron 锁定为 44.8.0；在 `tianshu_ui/` 执行 `npm ci` 后，还需执行 `npm run setup:electron`，由后端虚拟环境的 Python 联网下载官方运行时并校验包内 SHA256。下载器支持本机系统代理；失败时按提示检查网络/代理后重试，不要在反馈中复制私密代理地址或凭据。首次验收关闭模型及两路检索，使用 `case4` 计算，确认任务 ID、验证结果和报告对应一致后再尝试自己的数据。

`case4` 为自建的四节点模型，不是 IEEE 标准算例。源码中的其余演示/探针用于检查特定功能或错误处理。`case_broken` 故意缺少依赖；`case_nonconv` 为应力模型，不保证用默认迭代参数就返回“不收敛”。

新会话未指定案例的计算默认使用 `case4`；显式指定未提供的案例应返回缺失提示。若有上传文件或已有会话上下文，系统可能沿用对应案例；应查看任务卡和报告中的输入身份，确认计算的是预期数据。

## 上传与计算

在“分析工作台”新建会话，上传文件，再明确发送计算指令。支持：

| 输入 | 用法 |
|---|---|
| `.dss` | 入口文件及其引用的依赖文件需完整提供 |
| `.zip` | 打包入口和依赖，保留相对目录结构；建议以 `Master.dss` 为入口 |
| `.xlsx` | 使用转换器支持的 System/Bus/Line 等表结构 |
| `.csv/.json` | 使用项目支持的字段、单位和引用关系；普通任意表格不能直接视为电网模型 |
| `.m` | MATPOWER case 的受支持静态数据子集；不会执行任意 MATLAB 脚本 |

原生 DSS 的 `Redirect/Compile` 及文件型数据引用必须可解析；缺依赖、路径逃逸或不支持的动态引用会被拒绝。多文件案例应一并上传或打包，避免只上传入口。

表格转换的报告会声明模型口径与限制。Gs/Bs、π 型充电、无功限额等按支持范围建模；连续相移只适用于支持的平衡正序模型。若输入语义不受支持，应修正数据或选择适合的原生 DSS 表达，不应删除错误提示后继续使用结果。

## 批次、取消与恢复

明确提交多个案例时，系统形成持久化批次，逐项执行并展示各自任务及报告。某项失败后，其他项仍可继续。已成功项不会因“重试失败项”而重新计算。

运行项取消需要等待后端确认终态；等待项取消不创建求解任务。界面刷新保留已有记录。后端异常退出再启动时，在途项标记中断，待运行项暂停，使用界面的继续/重试操作恢复；已成功项保留。

取消、失败和中断任务中的原始数值可用于诊断，但不能与成功发布的验证结果混用。每项应核对自己的任务 ID、状态和报告链接。

## 阅读报告

重点查看输入身份、求解口径、状态、独立验证、母线电压、网损、设备负载率和限制。`success` 表示流程成功，不自动意味着所有电压或设备指标合格；“未评估”“不可用”也不等于零或正常。

数值结论以结构化结果和验证记录为准。模型解释仅用于组织语言，不能替代求解器或补充缺失的专业数值。历史追问可读取已有结果；需要新计算时明确说明“重新计算”。

默认产物位置相对于 `dpf_agent/`：

| 目录 | 内容 |
|---|---|
| `cases/` | 随源码附带的自建演示/探针 |
| `chat_data/` | SQLite 会话、上传副本和批次输入 |
| `tasks/<task_id>/` | 输入副本、状态、轨迹和诊断材料 |
| `outputs/<task_id>/` | 对外交付的报告和结构化结果 |

任务、上传、日志和报告可能包含用户数据及本机路径，属于本地运行数据，不应提交到公开仓库。

## 可选模型与知识数据

离线演示不需要密钥、Ollama 或知识库。启用模型时退出应用，在启动终端设置 `DPF_LLM_ENABLED=1`；可通过桌面“模型服务”页保存自己的接口地址、模型名和密钥，也可直接设置 `DPF_LLM_BASE_URL/DPF_LLM_MODEL/DPF_LLM_API_KEY`。启用后可能调用用户指定的外部服务，费用与数据传输由使用者配置决定。

桌面设置通常保存在 `%APPDATA%/tianshu-1/settings.json`，其中密钥为本机配置数据，不随源码包提供。示例 `.env.example` 不会自动载入；需显式设置环境变量。启用模型后应重新运行一个小案例，验证接口兼容性、解析与解释，而不是仅凭配置卡的“已配置”判断联调通过。

本源码版没有原始知识库和 IEEE 原始模型；如自行加入资料，应先确认使用和分发条件。需要本地检索时配置 `DPF_RAG_KNOWLEDGE_DIR` 并启用 `DPF_RAG_ENABLED`；外部 Power-RAG 服务需另行安装、配置和验收，不属于离线首次运行步骤。

## 验收边界

本轮在当前机器新建虚拟环境安装 31 个 Python 包，`pip check` 通过；首轮 37 套后台回归与 4 项 Node 检查通过。Electron 升级锁定后的 `npm audit` 当时报告 0 项已知漏洞。

CLI 的 `case4`、`case_tx` 和实际 Electron 44.8.0 窗口提交的 `case4`，合计 3 个真实 COM 完整任务均为 `success`、`verification.passed=true`，每项含独立复算。窗口验收使用空白用户配置，由桌面自动启动所属后台，实际点击工作台、新建会话、输入并发送任务；报告 HTTP 200，显式指定未附带的 `ieee33` 清楚提示缺失，页面错误数为 0，退出后 Electron 及所属 8000 后台正常回收。

1. 离线回归使用受控引擎替身，其中部分测试确实创建操作系统子进程；通过不能代表真实数值引擎已经运行。
2. Node 检查覆盖界面逻辑，实际 Electron 启动、上传、取消与恢复需要桌面交互验证。
3. `case4`、`case_tx` 的真实 COM 计算只覆盖这两个自建模型和当前机器环境；不等于 IEEE 馈线验证或所有转换格式均得到独立外部对照。
4. Windows 当前机器的新建虚拟环境能检查依赖完整性，不能证明未安装 OpenDSS 的全新系统已具备运行条件。引擎注册、硬件与替代引擎仍需单独检查。

独立评测模块 `dpf_agent.evals.run_conversion_fidelity`、`dpf_agent.evals.run_eval` 中的官方数据评测需要使用者自行提供获授权的相应模型和参照资料。本源码版没有附带这些资料，不把缺少官方数据的评测计为通过。
