## 安装与配置

1. 安装 Windows x64 Python 3.13、Node.js 24、OpenDSS，注册 `OpenDSSEngine.DSS` COM。在项目根目录创建 `dpf_agent/.venv`，用 `dpf_agent/requirements-windows-py313.lock.txt` 安装依赖。COM 检查与锁定依赖步骤见[根说明](../../README.md)。使用 Harness 主入口不需要为旧界面另装 Electron。
2. 单独安装 Harness，在 Harness 自身设置中配置有权限使用的联网模型。API 密钥与账户配置留在个人 profile，不写入项目。联网模式下，模型可接收对话、工具摘要和明确提供的数据；使用业务资料时按实际数据使用权限决定提供范围。
3. 首次安装天智五号插件时，按[插件说明](../../integrations/deepseek-harness/README.md)在私有准备副本填写四个绝对路径，核对包后通过 Harness 官方 CLI/管理入口安装。公共源码的配置保持空白；机器路径、凭据、审批、运行状态和带路径安装包不进入公开源码。已有 0.1.3-p4 部署不需为本轮入口与文档再次升级。
4. 先执行 `node scripts/start-harness.js --check-only` 检查已安装位置。需指定非标准位置时，执行 `node scripts/start-harness.js --harness-exe "<Harness.exe的绝对路径>"`；启动器只定位并启动已安装的官方程序，不下载、不安装、不设置模型。脚本参数与本机探测以启动器实际输出为准。
5. 打开 Harness，选择项目工作区、“天智五号”模式。先请求实际调用 `tianshu_capabilities`，核对插件版本和真实能力；看到预设、安装成功或启动器成功不单独代表求解验收通过。

退出使用 Harness 自身“应用→退出”。报告回环地址随服务重启可能失效，对原 task_id 再调用 `tianshu_open_report` 获取新地址，不需重算。不要同时启动两个版本去占用同一私有任务目录。

## 日常工程流程

1. 提供工作区内的 package_root、master_file 与完整 files 清单，先导入并核对实际返回的 snapshot_id 和检查状态。不要让 Agent 递归寻找文件或猜附件键。当前文件路径输入可直接使用；原生上传/流输入另列未验，不影响这个入口。
2. 明确频率、固定工况来源、工况确认声明和求解配置。需要工程越限校核时，另外提供项目确认的基值、设备额定和限值及来源；缺依据用 `criteria=null` 或标为未评估，不能让模型猜默认阈值。
3. 确认本次文件和计算授权后提交一次。按返回 task_id 等真实终态，区分 execution_status、numerical_validity、engineering_assessment；queued/收敛/报告生成均不自动等于工程合格。
4. 查看报告和结果追问时明确同一 task_id，要求返回原值、单位、measurement_basis 与位置/基值。纯只读追问不重新提交；改模型、工况、开关或明确限制前确认。
5. 停止操作须等待所属任务的真实取消确认。异常重启后原在途任务可标 interrupted，不自动重放；已提交结果继续只读。若要新计算，明确新请求，不把旧 task_id 当新结果。

输入中的中文来源说明建议单独逐行写 `key=value`；发送前核对可见内容，执行后核对保存的工况声明。已有一次拟稿与实际提交文本保真未通过的记录保留，不为修正说明而重写历史请求。

## 专业核心与扩展开发

专业核心可脱离 Harness，通过[CLI/回环 API](README.md#使用入口)调用。[数据合同](contracts.md)规定输入身份、状态和结构；[设备语义](device-semantics.md)、[观测口径](observations.md)、[工程判据](project-engineering.md)规定数值和判定边界。新增输入格式、求解器或规则须明确定义适用范围及验收，不得绕过强制验证。

[可运行只读扩展示例](../../examples/professional-extension/README.md)演示独立工具注册、已提交结果读取、身份检查及原生电压指标展示。它不提交潮流、不重算、不新增工程阈值或改写原权威结果；例子证明专业工具可扩展，未实现新的电压校核规则。

## 基准与复现

复现时固定模型文件及哈希、主文件/依赖清单、scenario/频率与工况、求解配置、适配器版本、项目判据来源、对照数据身份以及逐指标误差合同。比较完整任务的已提交结果，不将报告图示或同一引擎复算替代可信外部对照。参考接口及误差/覆盖规则见[参考比较](reference-comparison.md)、[报告包](report-bundle.md)和[P3限定参考状态](p3-reference-status.md)。

French17 固定 v3 是用户认可的限定工程参考；认可绑定模型、工况、判据、适配近似和对照结果。仍有 8 项变压器导体额定及 1 项网损依据缺失点，整体合规不作合格结论，engineering_ready=false。ENWL 仅用于软件链路/取消等测试，不扩大工程认可。IEEE4/13、浮置 YD 等历史失败维持原账，不因本轮文档和入口整理改称通过。性能数据只属于实际样本与环境，不设无依据的任意馈线规模保证。

## 回退与数据保全

本机桌面“启动天智五号”指向已安装的 Harness；“启动天智五号（旧版）”保留原 Electron 启动方式。源码用户运行 `scripts/start-legacy.bat` 或 `tianshu_ui/start-tianshu.bat`，前提是旧版 Node/Electron/Python/OpenDSS 依赖仍可用。入口文件的恢复只切换启动目标，不迁移数据，也不把两个服务合并为同一个状态目录。

旧版 `dpf_agent/chat_data`、tasks、outputs 及个人设置保留；专业核心私有 stateDir 独立保留模型快照、jobs/events、尝试、产物和凭据。Harness profile 保留原有会话/模型配置。停止相关进程后再备份这些目录，不在运行时覆盖SQLite或审批。无需为回退删除插件、重算历史、重置profile或拷贝旧结果到新任务。

当前电脑已配置路径存于本机部署及内部交付记录，不写入公共配置。开发树保留全部开发材料，本地发布树只同步公开所需功能和说明；GitHub按另行明确发布授权更新，本轮未上传。
