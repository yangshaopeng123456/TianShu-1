# 日常文件计算

日期：2026-10-27。维护：yangshaopeng。

在 Harness 的“天智五号”模式，选择工作区里的模型入口文件，保持其依赖在同一完整模型包目录，然后直接发送：

> 帮我计算这个文件。

不需要用户填写快照编号、场景编号、求解器对象、确认人或确认日期。0.1.5-daily在已有请求整理基础上，修复“只选Master.dss却要求手填所有依赖”的问题：Host在原生授权范围内读取入口的明确同包引用，固定完整快照，再计算现有运行点。这个能力只涉及受支持的输入子集，不能把任意DSS脚本当作可计算模型。本机已一次官方CLI冷升级至0.1.5-daily，17文件核对一致，原会话及知识库保留；安装版本与真实GUI效果分别记录；目前已有同一原始入口的隔离真实COM闭环证据，不把模拟Host授权写成真实GUI通过。

## 系统会自动处理什么

- 一个`.dss/.m`文件，或一组文件中唯一的`Master.dss`，可作为明确入口。日常workspace_files方式由Host整理包目录，并按入口中明确字面引用自动补齐同包依赖；不扫描目录或猜文件名。引用读取范围在原生授权中展示，限500文件/20MiB；完整清单和哈希保存后才导入。
- 频率只取已授权源文件与固定快照逐字绑定的明确声明，或受核心核验的MATPOWER转换参数。电源频率、设备基频不冒充求解频率，明确Set frequency是预期声明，CalcVoltageBases后保留该声明；实际求解仍强制读回核对，不能把源声明当作已实测频率。
- 使用原有工况，不改负荷、电源、开关、接线。日常策略为OpenDSS COM snapshot、最多100次迭代、容差1e-6、零自动重试，输出完整四域与HTML/JSON/CSV。
- 自动生成内部场景和Host声明记录，持久化完整请求；计算仍按同一请求SHA256取得原生授权。重复恢复同一调用复用原请求与任务，不换身份重算。
- 没有工程限值时继续有效潮流计算，`criteria:null`，缺依据项未评估，不强迫用户编限值，也不给工程合格结论。

## 什么时候只问必要的问题

| 情况 | 用户会看到的追问或说明 |
| --- | --- |
| 多个模型或主文件不明确 | “你要计算哪个文件？”并列实际文件名 |
| 频率缺失或静态上下文不能确定 | “本次按多少Hz计算？”；用户明确后交核心核对，不改模 |
| 已知频率互相矛盾 | 说明冲突，先核对模型；不能靠随便补一个频率掩盖矛盾 |
| 文件包不完整 | 指出实际缺少的相对文件名，请补回该文件或提供完整算例目录；不要求手填API文件清单 |
| MATPOWER缺源阻抗等必要输入 | 只询问缺失的专业参数，不补编相别或源阻抗 |
| CSV/JSON与XLSX | CSV/JSON须符合新tianzhi-grid/1.0；XLSX等旧转换未自动迁移，不能任意猜格式 |

用户已明确要求计算且数据完整时，不额外重复询问“是否计算”；具体文件读取和计算的原生授权仍按Harness策略进行。用户明确给出的求解约束、项目判据或工况修改不能被日常默认策略悄悄覆盖。

## 文件读取边界

自动补齐只用于工作区中已选入口的明确字面引用。父目录、外部/动态路径、链接、插件私有state、Host指定连接文件及凭据/配置路径均不自动读取。文件在整理过程中改变则停止，不拼接不同版本。用户明确只读已选文件时关闭include_dependencies；旧显式文件清单默认不扩大。原生附件只上传入口而没有依赖时，需要补附件或提供完整工作区模型目录，不能自动访问原上传位置。

当前内部Compile、叶脚本继续引用等不支持结构保持拒绝，显示受控原因；不会自动改模型以通过。新增CSV/JSON合同见[采购功能补齐](procurement-extensions.md)；XLSX等旧版能力不因此迁移。

## 声明与工程认可

日常模式的`confirmed_by`明确写作Host本次请求声明，`confirmed_at`是实际Host准备/声明时间，**不是用户签名、工程工况审核或审批完成时间**。这些字段满足现有1.1合同中“调用者声明”的含义；原生决定时间独立存于授权回执`decided_at`，完整请求在审批后不改变。

高级`request`方式继续保留调用者明确提供的原声明；不与日常`model`方式混合。内部记录和原生计算授权不提升工程认可。French17固定参考及9个缺依据点保持原范围，ENWL等软件流程样本不扩展工程认可。

本次优化沿用已有工作区路径输入；原生附件流专项仍未验，不能把文件标签或`@`引用说成已通过原生上传验收。接入、独立接口与回退见[联网版交付说明](online-delivery.md)。
